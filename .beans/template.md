## Resolution

## Conventions

Filename: `<prefix><id>--<slug>.md` (for example
`holon-agentic-coder-ref-metadata-0033--remove-the-native-host-mitmproxy-flag.md`)

- `<id>` is a strictly sequential 4-digit zero-padded integer (`0001` through `9999`), prefixed with the `prefix` value.
  Random base36 IDs generated by `beans create` (e.g. `k4t7`, `1lh8`) MUST NOT be used. To determine the next ID,
  inspect all existing files in `.beans/`, find the highest integer ID, increment by 1, and zero-pad to 4 digits (e.g.
  `0034`). The ID is **derived from the filename**, so it is never repeated as a frontmatter field; the `# <full id>`
  line above is only a cosmetic comment.
- `<slug>` is the human-readable title, lowercased, hyphenated, and truncated to 50 characters with no trailing hyphen.

Frontmatter fields that the `beans` CLI persists (any other key is dropped on the next CLI write, so it belongs in the
body instead):

| Field        | Notes                                                             |
| ------------ | ----------------------------------------------------------------- |
| `title`      | Required                                                          |
| `status`     | Required. `todo`, `in-progress`, `draft`, `completed`, `scrapped` |
| `type`       | `task`, `bug`, `feature`, `epic`, `milestone`                     |
| `priority`   | `critical`, `high`, `normal`, `low`, `deferred`                   |
| `tags`       | List of lowercase, hyphenated single words                        |
| `created_at` | Unquoted RFC3339 UTC                                              |
| `updated_at` | Unquoted RFC3339 UTC                                              |
| `order`      | Fractional index string for manual sorting                        |
| `parent`     | Parent bean ID                                                    |
| `blocking`   | Bean IDs this bean blocks                                         |
| `blocked_by` | Bean IDs blocking this bean                                       |

Fields that are **not** part of the CLI schema and therefore live in the body as Markdown: task description, notes,
resolution summary and assignee.
