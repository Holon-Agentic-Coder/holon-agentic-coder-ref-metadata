Install the official GitHub CLI (`gh`) into `holon-base` (and therefore all agent container images, including the review
loop agent), and add unit/integration tests verifying `gh` command availability and executable path resolution inside
the review loop agent container.

## Context & Problem Statement

During Stage 4 (PR Review Loop) of the Holon flow, the containerised **Holon Review Loop Agent**
(`HOLON_ROLE=review-loop`, dispatched to `sandbox_executor.entrypoint.review_loop`) runs inside container images such as
`holon/agent-antigravity`.

Upon completing consensus evaluations, `post_pr_review_consensus()` in `src/sandbox_executor/flow.py` attempts to
dual-post the review consensus to GitHub using `gh pr comment` and `gh pr review`.

However:

1. `apps/sandbox-executor/Dockerfile` builds `holon-base` from `python:3.13-slim` and installs only
   `git curl jq build-essential ca-certificates ssh vim shellcheck`.
2. The GitHub CLI (`gh`) is not installed in `holon-base` or any derived agent image (`agent-antigravity`,
   `agent-claude`, `agent-gemini`, `agent-opencode`, `agent-pi`, `agent-codex`, `holon-orchestrator`).
3. Consequently, `shutil.which("gh")` returns `None` inside the container. Both `gh pr comment` and `gh pr review` are
   silently skipped (`comment_attempted = False`, `review_attempted = False`), leaving pull requests without any review
   or approval comments on GitHub despite the review loop reporting consensus approval.

## Proposed Remediation

### 1. Install `gh` in `holon-base` Layer

In `apps/sandbox-executor/Dockerfile`, install the official GitHub CLI in the `holon-base` layer with multi-architecture
support (`amd64` / `arm64`) using either the official GitHub CLI Debian repository or official binary releases:

```dockerfile
# Install GitHub CLI (gh)
RUN dpkgArch="$(dpkg --print-architecture)" && \
    mkdir -p -m 755 /etc/apt/keyrings && \
    curl -fsSL https://cli.github.com/packages/githubcli-archive-keyring.gpg | tee /etc/apt/keyrings/githubcli-archive-keyring.gpg > /dev/null && \
    chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg && \
    echo "deb [arch=${dpkgArch} signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | tee /etc/apt/sources.list.d/github-cli.list > /dev/null && \
    apt-get update && \
    apt-get install -y --no-install-recommends gh && \
    rm -rf /var/lib/apt/lists/*
```

Because all agent layers (`agent-antigravity`, `agent-claude`, `agent-gemini`, `agent-opencode`, `agent-pi`,
`agent-codex`, `holon-orchestrator`) inherit `FROM holon-base`, `gh` will be immediately available in every agent image
and the review loop agent container.

### 2. Add Review Loop Availability Tests

1. **Unit Tests in `test_review_loop.py`**:
   - Assert `post_pr_review_consensus` raises or logs informative diagnostics when `gh` is missing vs when `gh` is
     present.
   - Verify that `shutil.which("gh")` resolution is tested and mocked properly for review-loop execution.
2. **Container Availability Test in `test_container_images.py` or `test_review_loop.py`**:
   - Add a test verifying `which gh` or `gh --version` inside the built agent/review-loop Docker image
     (`holon/agent-antigravity` or `holon/orchestrator`), ensuring the binary is present, executable by non-root user
     `holon` (UID 1000), and exits with returncode 0.

### 3. Verification

- Run `docker buildx bake` or target image build to verify clean multi-arch packaging.
- Run `uv run pytest` across `apps/sandbox-executor/tests` ensuring all unit and container tests pass.
- Format with Prettier before committing in the harness.
